# Annotate UI concept — image-generation prompts

Generated with Pi `codex_generate_image` (Codex backend), then refined in a
second image-edit call. The existing Annotate screenshot was a functionality
reference, not an edit target. These images are design proposals, not running UI.

## Base generation prompt

Use case: ui-mockup. Asset type: exploratory desktop product-design mockup for a local Pi coding-agent extension called Annotate. Image 1 is a REFERENCE of the current browser UI and its real features, NOT an edit target; redesign it from scratch with much better hierarchy and usability. Produce one polished, believable, shippable wide desktop web-app screenshot (roughly 16:9), straight-on, no device frame or marketing page.

Primary request: reimagine a review-and-annotation workspace for agent responses, changed files, generated output files and arbitrary file browsing. Practical three-pane layout: (1) restrained ~260px left navigation with a prominent 'Find files or paste a path…' search field and ⌘P hint; clearly separated 'Agent response', 'Changed files' grouped by folder, 'Opened files', 'Browse locations'. Show nested folders 'src' and '/tmp/run-42', with report.md, generate.py and results.json; results.json selected. (2) flexible central document viewer with a calm breadcrumb row 'Project / runs / exp-01 / results.json', a small 'Generated · no recorded diff' chip, Document active / Diff unavailable, Refresh control, a realistically formatted JSON or Markdown output preview with line numbers, ample legible whitespace, a subtle highlighted selection and an anchored annotation marker. (3) ~320px right 'Notes' rail with two concise review cards, exact short quote and comment, severity tag, edit action and a clear add-note control. Top toolbar with 'Annotate', session context, 'Last request' and 'Whole session' segmented scope. Persistent bottom action 'Done → Pi draft' and unobtrusive '2 notes saved locally · not sent' reassurance.

Style: refined macOS developer-tool aesthetic, Slate dark neutrals, subtle borders, high-contrast readable type, one cool blue accent and a restrained warm annotation color. Dense enough for actual use, but not cramped; crisp alignment, useful affordances, restrained iconography. Keep the interface obviously about reviewing local files, not a generic IDE or chat app. No demo mode, no gradient-heavy glassmorphism, no 3D, no people, no branding other than Annotate, no illegible filler paragraphs or watermark. Make the visible labels above as accurate and readable as possible. This is a conceptual mockup, not a claim of implemented behavior.
