# Annotate — UI/UX pass

Implemented: one folder-grouped **Files in review** list (captured and opened
files together), breadcrumbs, source/diff state, grouped search and recent
files, linked notes, local-save feedback with retry, a non-mutating Pi-draft
preview, collapsible rails, and narrower-window layout. The sections below
remain a design reference, not a claim that every advanced sub-item shipped.

Mockup: `annotate-ui-concept.png`. It illustrates hierarchy and interaction, not exact
current behavior. The mockup's separate “Generated / discovered” section was
**not adopted**; a file found on disk is merely discovered, not provably
generated by the agent. Do not show a Diff without a captured baseline.
The mockup's “Medium/Low” severity chips are illustrative; the current note
types are comment/suggestion/issue/praise. Avoid adding a second taxonomy
without deciding how it affects feedback.

## 1. Navigation and information architecture — first iteration

- Replace the long undifferentiated sidebar with **Agent response**, one
  **Files in review** tree (changed and opened files grouped by folder), and
  **Browse locations** (project + folders explicitly opened by the user).
  Never tag a path “external” merely because it lies outside Pi's cwd.
- One source identity per file, with a consistent selected state wherever it is
  referenced. Keep the current document open when new files arrive; never auto-
  switch while someone is annotating it.
- Add a breadcrumb above the document (`/tmp / run-42 / results.json`). Parent
  segments navigate or expand that directory; the file segment offers **Copy
  path**, **Reveal in tree**, and **Pin folder**. Show the full absolute path on
  hover; truncate the middle of long paths, not their filename.
- Make **Last request / Whole session** an obvious scope control. It filters
  recorded changes, not browse locations or pending notes. Explain that “Last
  request” can include several internal agent/tool turns.
- Make the sidebar resizable/collapsible and independently scrollable. The notes
  rail should also collapse without losing the current document.

## 2. Finding and browsing — first iteration

- Put search in the left rail and keep ⌘P/Ctrl+P. In the palette group results:
  **Recent**, **Changed**, **Files in opened locations**, and **Open exact path**.
  An exact `/tmp/` path is a deliberate folder-opening action; never silently
  index all of `/tmp`.
- Show a compact path subtitle and match highlight for same-named files.
  Arrow keys, Enter and Escape must be reliable. Retain a small recent-location
  list. Show progress/limits when a directory/search is truncated.
- In browse, distinguish directories, files, unsupported/binary files and
  missing files. Offer **Refresh folder** contextually instead of an unexplained
  ↻ button; preserve expanded folders and scroll position on polling.

## 3. Document and diff — second iteration

- Give the document a stable toolbar: clickable breadcrumb, source badge
  (**Captured change**, **Discovered on disk**, **Agent response**), version
  status, **Document / Diff** and Refresh. For no-baseline files, disable Diff
  with “No recorded before-version” rather than hiding it silently.
- Render Markdown but offer **Source** when raw syntax/line numbers matter.
  Use readable monospace for JSON, CSV, code and logs. Keep the 512 KiB safety
  cap initially; do not promise full support for images/PDFs until designed.
- Prefer inline diff for small changes; optionally add side-by-side later.
  Do not imply shell-generated outputs are captured or attributable to Pi.

## 4. Annotation loop — second iteration

- Clicking a note should scroll to and highlight its exact quote; clicking a
  marker in the document selects the corresponding note. Preserve the exact
  browser selection even when Markdown-to-source offsets are approximate.
- Show an unobtrusive gutter marker and a tiny selection toolbar; support
  keyboard annotation, editing and deletion with clear focus states.
- Explicit states: **Saved locally**, **Saving**, **Could not save — Retry**.
  When disk content changes, keep the frozen annotated version and offer a
  compare/refresh choice without silently moving notes to new text.
- Sticky bottom action **Done → Pi draft** with total note count. Preview the
  combined feedback and show that it appends to—not replaces—existing editor
  text. Never auto-send.

## 5. Polish and safety — alongside each iteration

- Purposeful empty states (“No captured edits in this request; browse files or
  select the agent response”), skeleton/loading states, a useful disconnected
  state after `/reload`, and error messages with a retry action.
- Keyboard focus/focus-return, screen-reader labels, contrast, zoom, narrow
  windows and theme parity (Slate/Paper/Midnight). Avoid icon-only actions
  without tooltips.
- Keep server token/loopback protections, explicit roots and symlink containment.
  Search must remain bounded. Do not add a global `/tmp` watcher as UI polish.

## Suggested implementation slices

1. **Navigation shell:** three-pane layout, collapsible/resizable rails,
   breadcrumb and source/status badges. No change to capture semantics.
2. **Search + browse:** grouped palette, path suggestions, contextual refresh,
   recent locations, truncation/error UX.
3. **Review interaction:** anchored note navigation, save/stale states, feedback
   preview and keyboard accessibility.
4. **Advanced views:** source toggle, better diff presentation, richer text-type
   renderers. Only then evaluate provenance of script outputs.

Acceptance: a reviewer can find an existing file, open `/tmp/run-42/`, distinguish
captured edits from discovered outputs, navigate back to its parent via breadcrumb,
leave a note, verify it saved, and append feedback to Pi's editor without
confusing a generated result for a recorded diff. The current file and unsent
notes must survive tree polling and scope switches.
